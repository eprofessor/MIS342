Project Purpose and Learning Outcomes

Project02 applies the ODBC/client-server concepts introduced in Formative08 and Summative08. LuckyTire will continue using Access as a familiar employee-facing application while selected shared data reside in MariaDB/MySQL.

After completing Part 1, you will be able to:

  1. Connect Access 365 to an external relational DBMS through ODBC.
  2. Distinguish linked server tables from local Access tables.
  3. Create and verify Access queries against linked data.
  4. Verify a controlled data change from both the Access and server perspectives.
  5. Explain the security and availability responsibilities introduced by client/server architecture.

Primary CLO alignment: CLO 9; supporting CLOs 4, 8, and 11.

Exercise 1 — Link LuckyTire Server Tables
  1. Create a blank Access database named Project02_LuckyTire.accdb.
  2. Use External Data > ODBC Database and choose Link to the data source by creating a linked table.
  3. Use only the approved course ODBC configuration. Link the instructor-designated LuckyTire tables.
  4. See IOT20, Exercise 2 or use the AI to configure 64-bit MySQL ODBC 8 Unicode driver
  5. Confirm the linked-table indicators in the Navigation Pane.
  6. Open at least two linked tables and compare a row count or representative value with the server-side viewer.
  7. Do not save a password in a location the instructor has not explicitly approved.

Exercise 2 — Query Linked Data
  1. Create a multi-table query using linked LuckyTire data. Use the actual key relationships provided by the server schema.
  2. Include at least one meaningful criterion, sort, or calculated value.
  3. Save the query as qryProject02LuckyTire.
  4. Run the query and record the returned row count.
  5. Verify at least two results against the linked source tables or server-side data.
  6. Open SQL View and identify which portions are Access SQL rather than MariaDB/MySQL server SQL.

Exercise 3 — Verify a Controlled Two-Way Change
  1. Use only the instructor-designated student-specific sandbox table or row. Do not modify shared production-like course data.
  2. From Access, make one small approved change, such as updating a sandbox note/value or adding a clearly fictional test record.
  3. Verify the change in the server-side viewer.
  4. Make a second approved change server-side and refresh/reopen the linked table in Access.
  5. Verify that Access displays the server-side change.
  6. Restore or remove test data if the assignment environment requires cleanup.
