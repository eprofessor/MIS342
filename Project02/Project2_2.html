Project Purpose and Learning Outcomes

Part 1 established the ODBC link. Part 2 turns that connection into a small client/server database application and evaluates where Access helps and where the server introduces new responsibilities.

After completing Part 2, you will be able to:

  1. Create Access forms/reports that use linked MariaDB/MySQL data.
  2. Compare local and linked-table behavior.
  3. Evaluate updateability, network availability, and permission dependencies.
  4. Test the application from both Access and the server perspective.

Primary CLO alignment: CLO 9; supporting CLOs 5, 6, 8, and 11.

Exercise 1 — Build an Access Front End
  1. Open the Access front end created in Project02 Part 1.
  2. Create a form using an appropriate linked LuckyTire table or linked-data query. Save it as frmProject02LinkedData.
  3. Create a report based on linked LuckyTire data. Save it as rptProject02LinkedData.
  4. Use a meaningful sort/group/summary in the report.
  5. Verify form records and one report value against the linked source data.

Exercise 2 — Compare Local and Linked Storage
  1. Choose one small instructor-approved linked table and import a local copy into Access using a clearly different name ending in _Local.
  2. Compare row counts, field types as Access sees them, and at least two values between the linked and local copies.
  3. Change one approved sandbox value on the server or linked table and note whether the local imported copy changes automatically.
  4. Refresh/reopen the linked table and verify its current server value.
  5. Document the difference between a snapshot/import and a live link.

Exercise 3 — Evaluate Client/Server Dependencies
  1. Identify the components required for the Access front end to reach MariaDB/MySQL: network/VPN, server, DBMS, ODBC driver, DSN/connection settings, account permissions, and Access.
  2. Use an instructor-approved method to observe one dependency failure or use a provided failure scenario if disconnecting is not appropriate.
  3. Record the user-visible symptom and the likely layer causing it.
  4. Use Direct Mode or optionally Hermes to develop a short troubleshooting sequence that does not expose credentials.
  5. Verify normal operation after the issue is resolved/restored.
