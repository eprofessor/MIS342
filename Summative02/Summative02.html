Assignment Purpose and Learning Outcomes

Formative02 introduced the difference between a flat file and normalized LuckyTire tables. Summative02 requires you to build and test the relational structure independently and demonstrate that the database prevents an invalid relationship.

After completing this assignment, you will be able to:

  1. Configure normalized customer, tire, and sales tables with appropriate primary keys and data types.
  2. Analyze repeated facts in a flat file and explain how normalization reduces redundancy.
  3. Create one-to-many relationships using compatible primary and foreign keys.
  4. Enforce and test referential integrity.
  5. Evaluate the business value of a normalized relational structure.

Primary course learning-outcome alignment: CLO 3, with supporting evidence for CLOs 2 and 8.

Questions 1 through 6 require concise answers of no more than 500 characters. The Final Assignment Reflection allows a longer response.

Exercise 1 — Table Structure and Normalization
  1. Open LuckyTire_FlatSales.csv and identify customer and tire facts repeated across multiple sales rows.
  2. Create a blank database named Summative02_LuckyTire.accdb.
  3. Import LuckyTire_tblCustomer.csv as tblCustomer; set CustID as the primary key.
  4. Import LuckyTire_tblTires.csv as tblTires; set PartID as the primary key and verify UnitPrice is Currency.
  5. Import LuckyTire_tblSales.csv as tblSales; set Invoice as the primary key and verify InvoiceDate, CustID, PartID, Quantity, and InvoicePaid use appropriate data types.
  6. Open tblSales in Design View and verify that CustID and PartID are compatible with the related primary-key data types.

Exercise 3 — Test the Integrity Rule
  1. Make a backup copy of Summative02_LuckyTire.accdb before testing.
  2. Open tblSales and begin a new record using a unique Invoice value.
  3. Enter CustID 999, which does not exist in tblCustomer, plus otherwise valid values.
  4. Attempt to save the record. Access should reject the record because referential integrity would create an orphan sale.
  5. Capture the Access message, then cancel/delete the incomplete test record so no invalid record remains.
  6. Verify that all original sales records are still present.
